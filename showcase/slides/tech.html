01 · Typo-tolerant search

"panner tika" → Paneer Tikka

frontend/lib/fuzzySearch.js
// 1. every menu word → character trigrams
"paneer" → " pa" "pan" "ane" "nee" "eer" "er "
"panner" → " pa" "pan" "ann" "nne" "ner" "er "

// 2. how close is each typed word to each menu word
dice   = 2 × shared ÷ total = 2×3 ÷ 12 = 0.50
edit   = 1 − 1 typo ÷ 6 letters      = 0.83  // swaps count as 1
sim    = max(dice, edit)  // below 0.45: no match

// 3. rare words matter more (IDF from the menu)
idf("tikka") = 3.36   idf("paneer") = 2.32   idf("veg") = 1.55

// 4. every typed word must match; rank by
score = Σ sim³ × idf      // cubed: close beats loose
      = 0.83³×2.32 + 0.80³×3.36 = 3.05

Measured on 39 misspelled searches

Substring search (before)26%
Right dish ranked first87%
Right dish in the top 10100%

Also finds manchoorian → Veg Manchurian, chiken biryani → Chicken Biryani, cofee → Cold Coffee.

Caveat: we wrote the typo list and tuned on it. Try your own.

02 · Deal me a dish

Online logistic regression, one step per swipe

backend/…/service/DealModel.java · DealLearningService.java
// a dish = sparse binary features
Paneer Kathi Roll, ₹129, veg →
  bias  stall:1  section:-  price:100-149  veg
  word:paneer  word:kathi  word:roll

// chance of a keep
p = sigmoid( Σ weights of its features )

// learn from one swipe (SGD + L2)
error = (kept ? 1 : 0) − p
w    += 0.15 × (error − 0.001 × w)

// fresh model, keep it once:
p: 0.50 → error 0.5 → each w += 0.075
next time: sigmoid(8 × 0.075) = 0.65

Shared + personal

A shared model learns from everyone. Each student's personal model starts from the shared model's prediction, so it only learns how they differ.

score = sigmoid(shared + personal)

Why words as features

Keeping paneer at one stall raises word:paneer everywhere. In tests, after 6 hands of keeping rolls and skipping coffee, an unseen Chicken Kathi Roll scores above coffee.

Privacy

Only swipes are stored; models are rebuilt from them at startup. Turning learning off deletes your swipes and retrains the shared model without you.

05 + 06 · On every dish

Similar, for less · Often sold out by

Similar, for less lib/similarDishes.js

Reuses the search model. likeness = score(candidate) ÷ score(dish itself), so 1.0 means the same words.

  • likeness ≥ 0.6, different stall, in stock
  • veg stays veg, non-veg stays non-veg
  • same size label: a half plate isn't a cheaper full one
  • no add-ons; one result per stall, at most 3

29% of dishes have a genuine cheaper look-alike. Oreo shake ₹147 → ₹85.

Often sold out by service/SoldOutService.java

A sold-out event is stored at the 3rd student report or when the stall unticks it. Time and dish only, not who reported.

// last 28 days, first sell-out per day
own   = median(dish's days)      = 14:10
stall = median(stall's days)     = 13:30
w     = days ÷ (days + 3)        = 4 ÷ 7
time  = w·own + (1−w)·stall → 15 min
      = "Often sold out by 2:00 PM"
// shown only after 3+ days: shrinkage
// stops 3 data points being trusted

Questions we get

Why not just use an LLM?

Cost and speed

Search runs in under a millisecond on the phone for free. An LLM call per keystroke would be slow and paid.

Privacy

Screenshots are read on the phone and never uploaded. Swipes can be deleted with one switch, and the model forgets you.

Measurable

Each model has a baseline and a number. We can say search went from 26% to 87%, not just that it "feels smarter".
